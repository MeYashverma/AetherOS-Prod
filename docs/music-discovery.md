# Music & Podcasts discovery

The app now opens to a catalogue-backed Discover screen instead of an empty lyric stage. Apple Music most-played / Apple Podcasts top-show feeds use the selected market (India by default; US/UK/Australia/Canada available). If charts fail, an explicitly labelled Apple catalogue search is attempted. Topic chips fetch music or podcast episode searches. Refresh and visible error/retry states are included; failures never become fabricated tracks. Results are cached for the session per market/view/topic. Overlapping refreshes cannot overwrite a newer response.

Artwork cards show title, artist/show and source capability. Artwork also appears in search results, Now Playing and recent listening. Only HTTPS media URLs without credentials are allowed; missing/failed images retain a styled initial tile. No stock image is represented as a real album cover.

Selecting music metadata uses the existing matching full-track resolver; chart/catalogue links are not audio and 30-second previews are never substituted. Podcast chart cards search episodes of that show. Episode results with publisher-provided HTTPS enclosure URLs use the existing native audio player. Existing lyrics, 17 visualization styles, Last.fm stats and playback controls remain in the Player view; the Discover/Player switch preserves active playback. The persistent YouTube dock hides while browsing without moving its iframe.

Artwork/catalogue requests go to Apple and its image hosts; playback and lyric providers remain the existing services. No API key is needed for discovery, but network/CORS/provider availability is not guaranteed. No discovery proxy or new credentials added. Cache shell-v97/discovery-1.

## Player layout and actual companion integration

The current PlaybackManager now exposes a read-only activity projection through AetherMusic.getActivity(): identity, artwork, adapter-backed time/duration, active/playing/ended state, lyric lines and estimated-timing flag. The companion no longer relies only on the legacy audioStream/_currentTrackAudio fields. Its music card follows the real YouTube/Audio/MusicKit adapter clock, supports seek-back updates and play/pause, and shows artwork/progress. The action tray transport/volume, live activity row, collapsed song label and local “what’s playing?” answer use this projection too. Legacy radio remains a fallback. Lyric updates are not notification spam: separate transition-deduplicated now-playing, paused, finished and error notices enter live alerts. Playback polling continues while the app is minimized so the companion remains current; no synthetic clock is added.

Album identity is now a compact 56px card (48px narrow) instead of a large duplicate cover. Video and lyrics share the main canvas side by side on wide windows; narrow layouts scroll the content. Classic lyric scrolling is contained to its own scroller so it cannot unexpectedly shift the entire player. The persistent video dock now inherits the media window's stacking level (below companion/system overlays) and hides on lock; its iframe is still never moved on rerender.

## Adaptive video and quieter controls

Video dock now fits source aspect ratio inside its layout slot instead of stretching to a grid cell. YouTube oEmbed dimensions are fetched asynchronously per selected source and session-cached; invalid/missing metadata defaults to 16:9. Superseded requests cannot resize a newer track. Square/portrait/wide fitting never crops the official player, and minimum slot dimensions accommodate its controls. Surrounding space uses the app's ambient material, not an added black panel. Letterboxing encoded in an upload, or supplied inside the cross-origin YouTube player, cannot be detected/cropped reliably by this app; no promise that every source loses its bars.

Primary scene toolbar now contains only labelled scene selection and fullscreen. Timing offsets/import live behind a closed disclosure. StickersAPI switch, media picker, lyric sync diagnostics and provider setup are under Playback & lyric settings. Existing element IDs/actions are retained. Defaults keep advanced settings collapsed.

Validation: 296 JS tests passed. New fit tests cover wide/square/portrait aspect preservation, invalid metadata and zero-size layouts. Controlled browser checks confirmed a 16:9 actual dock, collapsed advanced controls, preserved companion lyrics/seek/transport/live notice flow, and zero page errors using the mocked playback fixture. ## Fill correction (supersedes no-crop default above)

User confirmed Fit still showed source pillarboxing. Music videos now default to an explicit square Fill viewport: the source iframe retains its metadata aspect ratio but is enlarged/centered inside an overflow-clipped square. This removes centered side bars around square album-art recordings rather than merely resizing the outer layout. It can crop the picture and YouTube's edge controls; the visible Fill/Fit button restores the complete player in Fit mode. The choice persists via music_video_fit. This is a deliberate album-art crop, not automatic black-bar detection or a guarantee for all source compositions. Existing app transport/seek/volume remain outside the crop.

Validation: 297 JS tests passed; browser regression checked square Fill viewport, enlarged source, toggling back to uncropped 16:9 Fit and back, plus companion lyrics/playback/notices with zero errors. A labelled pillarboxed SVG fixture visually confirmed side-bar removal (/tmp/music-player-fill-desktop.png); external YouTube playback not independently tested. Cache shell-v100/discovery-4.

## Startup ownership / old Nightwave fallback fix

A screenshot exposed the retired renderer appearing when the new module did not register. This could happen silently on an import failure (including mixed cached versions of first-party helper exports). The entrypoint now loads a small classic bootstrap that owns os.renderMediaDashboard immediately, shows a loading state, imports the versioned player, and displays explicit slow/error/reload states rather than substituting the retired interface. The legacy renderer delegates to this owner even when an old callback holds a reference to it. Current player exposes its renderer for stable delegation. Helper imports and shell cache URLs are version-aligned (discovery-5/shell-v101); updated legacy script URL matches its actual entrypoint URL. Service worker no longer responds to missing script assets with index.html; HTML fallback is limited to navigation.

Validation: 301 JS tests + 9 server tests pass. Startup unit tests cover loading ownership, old callback delegation, success/failure and asset version alignment. Chromium passed the existing playback/companion suite with the new bootstrap, then deliberately served a helper missing fillVideo to reproduce an import failure: the media window showed the explicit startup error, not Nightwave, with zero unhandled page errors. The user's precise cache contents were not available for inspection, so a specific cached-export failure is a plausible mechanism, not a confirmed diagnosis of their browser. No saved workspace or settings were cleared.

## Controls-safe Fill

Fill now crops only during uninterrupted playing. Pointer hover, keyboard focus (including focus inside the iframe), touch interaction, paused playback and buffering use aspect-preserving Fit inside the same viewport, so the complete iframe/control edges are contained. Touch keeps controls visible until an outside interaction; explicit Fit remains permanent. The viewport does not resize during reveal, avoiding hover-boundary flicker. No provider controls are covered by an app overlay; the iframe is not recreated. Bars necessarily return while the complete player is shown.

Validation: 302 JS tests pass. Geometry regressions cover control-safe modes. Controlled Chromium checked hover/focus reveal and actual child-frame containment, pause reveal, toggle behavior and companion timeline/transport/notices with zero page errors. This uses a mocked adapter/fixture rather than a live cross-origin YouTube certification. Version-aligned entry/import graph discovery-6, shell-v102.
